# AnTiks Text-to-SQL

A local web assistant that turns natural-language questions into SQL over Excel files you upload. Workbooks are loaded into a DuckDB sandbox, relationships between tables are detected automatically (and can be edited on a schema board), and SQL is generated by the open-source `defog/sqlcoder-7b-2` model running on your machine. Generated SQL is sanitized against the loaded schema, executed in DuckDB, and the result is shown in the chat UI.

## How it works

- **Server** (`text_to_sql_app/server.py`): a FastAPI app that serves the single-page UI (`templates/index.html`, `static/style.css`) and the JSON API. Uploaded tables, the vector store and relationship state are kept under `~/.antiks/` (`data/sandbox.duckdb`, `vector_store/`, `datasets.json`).
- **Excel loading** (`load_excel.py`): reads one sheet of an `.xlsx`/`.xls` file with pandas (all columns as text) and creates a DuckDB table from it.
- **Relationship detection** (`relationship_detector.py`): profiles columns and scores candidate joins using name similarity, foreign-key naming patterns and value overlap. It runs after each upload and on refresh; relationships you define manually take precedence over detected ones.
- **Query parsing** (`multi_table_query_parser.py`, `column_alternatives.py`): matches words in the question to columns and values, identifies aggregations, grouping and ordering, works out which tables and joins are needed, and suggests alternative columns.
- **SQL generation** (`text_to_sql_optimized.py`): `TextToSQLSystem` indexes table metadata in ChromaDB using `all-MiniLM-L6-v2` embeddings, builds a single-table or multi-table prompt, and calls the model. A GGUF build is run through `llama-cpp-python` when one is found in the Hugging Face cache; otherwise it falls back to `transformers`. The output is sanitized (tables, columns, literals, numeric casts), validated, executed, and retried up to three times on error.
- `text_to_sql_architecture.py` is the earlier SQLite/transformers version; it still provides the shared `MetadataExtractor`, `VectorStore` and `SQLExecutor` classes.

API endpoints:

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Chat UI |
| `POST` | `/api/query` | Answer a question; body `{"message": "..."}`, returns an HTML reply |
| `POST` | `/api/upload` | Upload an Excel file (form fields `file`, `table`, `sheet`) |
| `GET` | `/api/datasets` | List loaded tables and their aliases |
| `DELETE` | `/api/datasets/{alias}` | Drop a table |
| `GET` | `/api/schema/{alias}` | Column names for a table |
| `GET` / `POST` | `/api/relationships` | Read or save relationships and schema-board positions |
| `POST` | `/api/refresh` | Re-detect relationships and reload the system |

## Getting started

### Prerequisites

- Python 3.8 or newer
- The `defog/sqlcoder-7b-2` model. For the GGUF backend, a `.gguf` file for that model must be present in the Hugging Face cache (`~/.cache/huggingface/hub`); the code prefers Q5_K_M or Q4_K_M files. The server sets `n_gpu_layers=-1` (full GPU offload), which the code targets at Apple Silicon with Metal.

### Install

```bash
./setup_env.sh                       # creates text_to_sql_env and installs requirements_text_to_sql.txt
source text_to_sql_env/bin/activate
./setup_gguf.sh                      # optional, macOS: llama-cpp-python with Metal support
```

No environment variables are required.

### Run

From the repository root:

```bash
uvicorn text_to_sql_app.server:app --port 8000
```

Then open http://localhost:8000.

## Usage

1. Upload an Excel file and give it a table name (letters, digits and underscores). Repeat for related tables; detected relationships are reported after each upload.
2. Open the **Schema board** next to a dataset to review detected joins, add manual ones, or change the join type.
3. Ask a question in the chat, for example "Show customer names with their total order amounts".

The same steps over HTTP:

```bash
curl -F "file=@customers.xlsx" -F "table=customers" http://localhost:8000/api/upload
curl -F "file=@orders.xlsx" -F "table=orders" http://localhost:8000/api/upload
curl -X POST http://localhost:8000/api/query \
  -H "Content-Type: application/json" \
  -d '{"message": "Show customer names with their total order amounts"}'
```

A workbook can also be loaded from the command line (restart the server afterwards):

```bash
python -m text_to_sql_app.load_excel path/to/file.xlsx --table customers --sheet 1
```

`QUICK_START.md` has a longer walkthrough with sample tables and expected SQL.

## Status / limitations

- State is global to the server process and stored in `~/.antiks/`; there are no user accounts or sessions.
- Only Excel uploads are supported, one sheet per upload, and all columns are loaded as text.
- `load_excel.py` writes an intermediate Parquet file through pandas, which needs a Parquet engine such as `pyarrow`; none is listed explicitly in `requirements_text_to_sql.txt`.
- `llama-cpp-python` is not in the requirements file; without it, or without a GGUF file in the cache, the system falls back to loading the model with `transformers`.
- `setup_gguf.sh` exits on anything other than macOS.
